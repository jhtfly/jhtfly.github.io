## 为什么是 GitHub Pages

个人网站最省钱的路线：**GitHub Pages**。它的原理一句话能说清——GitHub 免费把你仓库里的文件变成一个网站。不用买服务器，不用装环境，仓库即网站。

## 核心概念三句话

1. **仓库（Repository）**：带版本历史的云盘文件夹
2. **Pages**：把仓库文件“原样”发布成网站的免费服务
3. **网址**：`用户名.github.io/仓库名/文件路径`，一一映射

特别地，如果仓库名恰好是 `用户名.github.io`，它就是你的**个人主站**，直接用根网址访问，不挂仓库名路径。

## 搭建步骤概览

1. 在 GitHub 新建仓库，名字取 `用户名.github.io`
2. 写好 `index.html` 推送上去
3. 在仓库 Settings → Pages 里确认已从 `main` 分支发布
4. 等约 1 分钟构建，访问 `https://用户名.github.io/`

## 前端能简化到什么程度

不需要 React、不需要构建工具。一个 HTML 文件 + 一个 CSS 文件就能跑。做多个页面时用一个共享样式表，各页面保持同一套外观。数据类的列表（比如博客文章）可以用一个 `posts.json` 存目录，页面加载时用 `fetch` 读取——相当于一个手搓的迷你 CMS。

## 额度与限制

公开仓库完全免费：单站 1 GB 以内、每月 100 GB 流量软上限、每小时最多 10 次自动构建。对个人网站来说，这些数字基本等于“没有限制”。

## 注意两个小坑

- **文件名大小写要和网址一致**：Pages 服务器区分大小写，`Blog.html` 和 `blog.html` 是两个东西
- **中文文件名会变成 URL 编码**：推送前把文件改成英文名，链接才好分享
